# postquality.com

The public home of Post Quality Manager, the WordPress plugin: a static site served by GitHub Pages at https://postquality.com (Jekyll, built by GitHub Pages). It uses its own layouts and one stylesheet, no theme, no JavaScript, no web font and no third-party request.

- `index.html`: the home page. `pricing.html`: the pricing page (the Pro packs first, then the Free and Pro table and the FAQ). `docs.md`: the documentation page, its sections anchored (the home page links `#getting-n8n` and `#cost`).
- `_data/pricing.yml`: the three Pro packs, their prices, Freemius's checkout address and the nine pricing IDs (three currencies × three packs), read by `pricing.html`. The record is `docs/distribution.md` in the plugin repository: change a price or an ID there first, then here.
- `privacy.md`, `terms.md`, `refund.md`, `support.md`: the policies. Their source of truth is `docs/policies/` in the plugin repository; change them there first, then copy here: keep the front matter, drop the source's `# Title` line (the layout prints `page.title` as the h1).
- `_layouts/default.html` (every page: skip link, header, `main`, footer) and `_layouts/page.html` (text pages: the h1 and a 720 px column; `icon: true` in the front matter adds the 64 px icon, used by the 404).
- `_includes/`: `head.html` (SEO tags, the stylesheet, the favicon, and on the home page a `SoftwareApplication` JSON-LD), `header.html` (lockup B on the band strip, the Main nav, the Menu below 1000 px), `footer.html`, `lockup.html` (the icon plus the name as live text, variants B and D), `site-action.html` and `interest-href.html` (the site-wide action and the interest email), `screenshot.html` (a framed, captioned plugin picture), `icons.html` (inline SVG line icons).
- `assets/css/site.css`: the design tokens as CSS custom properties and every component, from the design spine in the plugin repository (story 86). `assets/img/`: the plugin pictures, each as WebP with a PNG fallback, under 250 KB. Today they are illustrations with fictional data, captioned as such; real captures replace them under the same names.
- `assets/icon.svg`, `assets/icon-128x128.png`: the brand icon (favicon, lockup, 404). Never edited here.
- `assets/og-card.png`: the sharing card (1200 × 630), shown when a page's link is shared. Its source is `_tools/og-card.html`, which Jekyll does not publish (folders starting with `_`).
- `_includes/signature.html`: the author's signature at the foot of every page, linking to heimvin.me. Its glyph is the Material Symbols "fingerprint" icon by Google, under the Apache License 2.0 (https://www.apache.org/licenses/LICENSE-2.0).
- `404.html`, `robots.txt`: the missing-page page and the crawler rules; `jekyll-sitemap` writes `sitemap.xml`.
- `CNAME`: the custom domain.

**Launch flag.** `_config.yml` carries `launched: false`. Until launch, every action is the interest email (`mailto:` with a fixed subject; its body names the page it was sent from) and no install or buy link renders. At the release, one edit to `_config.yml`: `launched: true` and the five values under it (`version`, `version_date`, `tested_up_to`, `wporg_url`, `changelog_url`). Then the header, hero, Free card and closing action lead to **Get the free plugin**, the hero shows the requirement line and the version line, What you need ends with **Install from WordPress.org**, and the documentation's Getting started opens with it. `/pricing/` shows the currency switch (USD, EUR, CHF; radio buttons and CSS `:has()`, no script, nothing stored, USD on every load; without `:has()` all three currencies show) and one **Buy** link per pack to Freemius's hosted checkout; the documentation's cost answer drops "A worked cost example is coming.", so the example (plugin story 49) belongs there by then; and the home page's `SoftwareApplication` JSON-LD gains its `offers` (Free, then Pro). Check the flipped state locally first, with the local build's settings and an overlay config: `JEKYLL_ENV=production PAGES_REPO_NWO=vincentheimann/postquality.com bundle exec jekyll build --baseurl "" --config _config.yml,<a file with launched: true and the five values>`.

**Documentation drift.** `docs.md` restates the plugin: its requirements, the setup guide's labels and steps, the manual setup, and the FAQ answers come from the plugin repository (`post-quality-manager/readme.txt`, `README.md`, the setup guide's strings in `src/setup/` and `src/n8n-connection/`, the n8n Workflow page, `docs/policies/`). Before publishing a change to either side, compare them: each fact sentence in `docs.md` is paired with its source sentence in the plugin, both must be found word for word, and every bold label in `docs.md` must be one of the plugin's own interface strings (or a WordPress screen, named as such). The plugin's admin menu still reads "Content Quality" until its naming sweep (plugin story 41); the page already says **Post Quality → n8n Workflow**. The pricing FAQ's "What counts as a site?" answers in plain words with every fact of section 3 of the terms, and links to it: change the terms first.

**Discoverability.** `jekyll-seo-tag` writes each page's `<title>`, description, canonical URL, Open Graph and Twitter tags and a JSON-LD block (`WebSite` on the home page, `WebPage` on the others). Every page carries a one-sentence `description:` in its front matter, unique to it (the site's `description` in `_config.yml` is the tagline, used by the footer and the home page's JSON-LD); `tagline` in `_config.yml` completes the home page's `<title>`. The `defaults` in `_config.yml` give every page the sharing card as its image (a plain path), which also makes the Twitter card the large one; `head.html` adds the card's size and its alt text, built from the site's title and description. `head.html` also adds the `SoftwareApplication` JSON-LD on the home page; its `offers` (the free plugin at 0, then Pro's 1-site price in USD, EUR and CHF from `_data/pricing.yml`) appear only with `launched: true`.

**Sharing card.** Rendered once, never by GitHub Pages (it does no image processing). After a change to `_tools/og-card.html` (the tagline, the lockup), render it at 1200 × 630 with headless Edge or Chrome and its own throwaway profile, for example `msedge --headless=new --hide-scrollbars --user-data-dir=<a new folder> --window-size=1200,630 --screenshot=<out.png> <file URL of _tools/og-card.html>`, check the picture, and save it as `assets/og-card.png` (under 250 KB). Platforms cache the card; a changed card may show only after their cache expires.

`theme: null` keeps GitHub Pages from applying its default theme (Primer) on top of the site's own layouts.

Local build (optional, GitHub Pages builds on push): `bundle config set --local path vendor/bundle` (the setting lives in the ignored `.bundle/`, so a fresh clone needs it; gems go to the ignored `vendor/`), `bundle install`, then `JEKYLL_ENV=production PAGES_REPO_NWO=vincentheimann/postquality.com bundle exec jekyll build --baseurl ""`. Without a GitHub token, `jekyll-github-metadata` cannot find the repository and guesses a `/pages/...` base URL; the two settings stand in for what GitHub Pages knows on its own. On Windows, the Ruby with the DevKit is `C:/Ruby32-x64` (some gems build native extensions); run Bundler with `MSYSTEM` and `MSYS` unset.
